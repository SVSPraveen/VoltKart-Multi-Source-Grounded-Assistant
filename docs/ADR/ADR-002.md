# ADR-002: Tabular Storage & SQL Sandbox Engine

## Status
Accepted

## Context
The system processes uploaded relational CSV tables, infers schema relationships, and executes LLM-generated SQL queries to compute exact metrics. Queries must never modify data, access host files, or introduce security vulnerabilities.

## Decision
Use **DuckDB** with dual connection architecture:
1. **Read-Write Ingestion Connection:** Used exclusively during file upload to profile schemas and write tables.
2. **Read-Only Sandbox Connection:** Used for LLM-generated query execution with `SET enable_external_access = false;` and read-only mode enabled.
3. **AST Validation:** Pre-execution AST validation via `sqlglot` enforcing single `exp.Select` statements and an identifier allowlist.

## Alternatives Rejected
1. **SQLite:** Inferior analytical capabilities (limited window functions and analytical date formatting compared to DuckDB).
2. **Pandas `eval()` / `df.query()`:** Prone to prompt injection and arbitrary Python code execution vulnerabilities.

## Executive Trade-off Analysis
- **User Value:** Sub-millisecond analytical query execution with zero background database daemons.
- **Risk:** Multi-threaded file lock contention; mitigated by opening secondary connections strictly in read-only mode.
- **Cost to Reverse:** Medium.
