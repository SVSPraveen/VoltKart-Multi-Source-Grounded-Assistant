# ADR-005: Streaming Protocol & Verification Order

## Status
Accepted

## Context
Standard LLM chat applications stream generated tokens raw to the client as they arrive from the model. However, in an evidence-first system where incorrect numbers or fabricated citations are strictly forbidden, streaming raw tokens risks showing ungrounded numbers to the user before they can be verified.

## Decision
1. Stream **Pipeline Status Events** live via Server-Sent Events (SSE) (e.g., `status: "Searching documents..."`, `status: "Executing analytical SQL..."`).
2. Run deterministic **Numeric Grounding** and **Verbatim Quote Verification** in backend code *before* streaming or finalizing the answer tokens.
3. Stream the validated answer immediately following successful verification.

## Alternatives Rejected
1. **Raw Token-by-Token Streaming:** Discarding or amending tokens after the user has already read them creates a jarring UX and destroys user trust.

## Executive Trade-off Analysis
- **User Value:** Absolute guarantee that no unverified or hallucinatory number is ever displayed in the UI.
- **Risk:** Perceived latency before answer text begins (~1.5s). Mitigated by informative live pipeline status indicators.
- **Cost to Reverse:** Low.
