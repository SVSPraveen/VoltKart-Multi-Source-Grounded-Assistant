# ADR-007: Web Search Tool Integration & Server-Side Gating

## Status
Accepted

## Context
Bonus requirement B8 specifies an optional web search tool toggled per message. The system must guarantee that when the toggle is off, zero outbound network calls occur. When toggled on, it must retrieve current factual data without hallucinating or relying purely on snippet summaries.

## Decision
1. **Server-Side Tool Gating:** When `web_search_enabled = false` on an incoming message, the search tool is completely omitted from the agent's toolset. Tests strictly assert zero network calls.
2. **Provider Gating:** Use Tavily API if `TAVILY_API_KEY` is configured; otherwise fallback to keyless DuckDuckGo search (`ddgs`) to ensure the project runs out-of-the-box on fresh test environments.
3. **Deep Retrieval:** Fetch and extract full webpage text for top results rather than trusting search engine snippet text.

## Alternatives Rejected
1. **Client-Side Search:** Insecure and difficult to audit.
2. **Prompt-Only Gating:** Directing the LLM "do not call search unless requested" often leaks search calls on ambiguous queries.

## Executive Trade-off Analysis
- **User Value:** Verifiable isolation, zero search call leakage, graceful offline/fallback behavior.
- **Risk:** Search rate limits; mitigated by provider caching.
- **Cost to Reverse:** Low.
